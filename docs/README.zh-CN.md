# 御膳房（home-menu）说明

家里用的电子菜单网站：家庭成员一起看菜、排一周菜单，还能从本周菜单生成买菜单。这页记的是它现在怎么用、数据怎么走、网站怎么发布，以及什么时候需要管理员亲自出手。部署状态、最新提交这类会变的信息不写在这里，以仓库的 PR、Actions 和 Vercel 部署记录为准。

## 这是什么

御膳房是一个家用电子菜单网站，界面以中文为主。你会做的菜记在这里，家庭成员像在餐厅看菜单一样挑菜，排进一周的早餐、午餐和晚餐。代码仓库开源，许可证是 MIT。

全站在登录后才能看到菜单。现在用的是全家共用一套用户名和密码，没有「每人一个账号」的用户表；密码只存在托管环境变量里，不进仓库，也不要发到聊天里。

## 能做什么

| 功能 | 说明 |
| --- | --- |
| 菜品墙 | 首页是菜品卡片，按分类筛选。有水彩插画的会显出来，没有的用菜名来补。点进去能看做法。「做过」会跟着 Notion 里的「已尝试?」走。 |
| 一周菜单 | 把菜排进星期一到日的早餐、午餐、晚餐。也可以加外卖、聚餐这类自定义项目，支持拖拽或「移到…」。周次按美国太平洋时间起算。 |
| 买菜单 | 从本周已点的菜里汇总食材，按分类排好，可选食材和「家里常备」会折起来。全家共用一份勾选，勾过的会同步到数据库。这个能力已在正式站上。 |
| 家庭登录 | 全家共用一套用户名和密码。登录凭据只存在托管环境变量里，不要发到聊天里，也不要写进仓库。 |
| 从 Notion 同步 | 菜谱从 Notion 导入，只读不写。登录后可以点「从 Notion 同步」；每天还会自动跑一次。才刚补上的食材要等同步完成，才会出现在买菜单里。酒单用同一次同步。 |
| 酒单 | 只浏览鸡尾酒：照片或毛笔字、基酒和口味、配料、步骤、出处。不排进一周菜单，也不进买菜单。 |

## 数据怎么走

菜谱的正文仍然住在 Notion 里，网站只读取，不会改 Notion。同步把有做法步骤的菜写进 Neon Postgres。家庭成员排的周菜单、买菜单勾选，都只存在 Neon 里。

数据流向：

- Notion 菜谱库（只读，不写回去）把菜名、分类、食材、做法交给同步
- 同步（站内按钮，或每天定时）把菜品写入 Neon Postgres
- Neon Postgres 存菜品、周菜单、买菜单勾选，供御膳房网站展示
- 御膳房网站（电脑、手机、带鱼屏）把点菜和勾选写回 Neon

买菜单只看各道菜在 Notion 里的「需要食材」属性，不会从做法正文里猜。刚补上的食材，要再同步一次才会进数据库。登录后点「从 Notion 同步」就可以；也可以等每天自动跑的那次。定时任务在 12:00 UTC，大约是太平洋标准时间凌晨 4 点，夏令时是 5 点。Hobby 档可能在那一小时里的某个时刻才真正跑起来。

## 怎么发布和上线

代码在本仓库，默认分支是 `main`。日常改动由云端编码 agent 编写，技术负责人审查和合并。合进 `main` 之后，Vercel 会自动发布到正式站。

- 每个 PR 都会有自己的预览地址，方便先看、先测，不会直接动到正式站。
- `main` 上有规则集 `main-protection`：要走 PR，并且 CI 里名为 `checks` 的那一项必须通过（包括 lint、类型检查、单测、生产构建，还有钉在本地的浏览器测试）。
- 另一条 `preview-e2e` 会针对预览地址再跑一遍浏览器测试，它不是合并的必要条件，但结果会写在 PR 下面。
- #34 加进去的 `pr-status-comment` 会在每个同仓库 PR 下面贴一条状态评论，汇总 `checks`、`preview-e2e` 和 Vercel 预览的结果。
- CI 跑完以后还会发一条通知给技术负责人，用来看结果，不影响构建本身是否算通过。
- 生产环境构建时会跑数据库迁移，但不会自动塞进示例菜数据。

数据库还有一条叫 `neon-ops` 的手动任务，在 GitHub Actions 里点开跑。默认是看同步报告；若选 `snapshot`，会建一个备份分支，默认 7 天后过期。Neon 免费档每个项目最多 10 个分支，跟预览库共用这个名额，所以备份默认不会永久留着。

## 花钱事

现在看到的都走免费档。这次核对时，正式站部署记录的是 Vercel Hobby；仓库说明里 Neon 用的也是免费档，并且项目已经接了 Vercel 上的 Neon 集成。没有看到已经开通的付费方案。

免费档也有额度。值得留意的是：Vercel Hobby 的日常构建和每日一次定时任务、Neon 免费档的 10 个分支上限（预览库和备份分支要一起算）。以后任何要花钱的步骤，都会先说明金额，得到确认再动。

## 什么时候需要管理员动手

大部分日常发布不需要额外操作。下面这些需要管理员来做，或者做了更省事。

- 登录正式站
    - 用托管环境变量里配置的家庭共享账号。用户名和密码不要发到聊天里，也不要写进仓库。
- 测某个 PR 的预览
    - 预览和正式站不用同一套密码。使用预览环境单独配置的测试账号，到该 PR 的预览地址登录。
- 刚在 Notion 里补了食材
    - 登录正式站，点一下「从 Notion 同步」；也可以等每天那次自动同步。不同步，买菜单里不会出现新填的食材。
- 想收到仓库通知
    - 可以在 GitHub 上 Watch 本仓库。这不影响发布，只是让维护者能看到提交和发布动作。
- 要花钱的时候
    - 任何付费步骤都会先说明金额并征求确认，不会自行开通。
